# Этап 4 — пользователи и корзина

Этап добавляет регистрацию и вход, редактирование профиля, смену пароля,
загрузку и удаление аватара, а также корзину для гостя и авторизованного
покупателя. Корзина хранится в сессии: она сохраняется при входе и выходе в
том же браузере. Заказы и оплата относятся к следующим этапам и здесь не
создаются.

## API

- `POST /api/sign-up` — регистрация с именем, логином, email и паролем;
- `POST /api/sign-in`, `POST /api/sign-out` — вход и выход;
- `GET /api/profile`, `POST /api/profile` — просмотр и обновление профиля;
- `POST /api/profile/password` — смена пароля с проверкой текущего;
- `POST /api/profile/avatar`, `DELETE /api/profile/avatar` — загрузка и удаление аватара;
- `GET /api/basket`, `POST /api/basket`, `DELETE /api/basket` — просмотр,
  добавление и уменьшение количества товаров.

Поля проверяются на сервере. Email проверяется как адрес и уникален без учёта
регистра; телефон должен быть пустым или в международном формате вида
`+79991234567`; пароль проходит активные Django password validators. Аватар
проверяется по реальному содержимому и ограничен 2 МиБ. Количество в корзине —
целое число от 1 до 999 и не может превышать остаток доступного предложения.
Ошибки API возвращаются как `{"errors": {"field": "сообщение"}}`.

Форма регистрации исходного фронтенда не запрашивала email, хотя модель
пользователя требует его. В этом этапе email добавлен в интерфейс и контракт
Swagger; для профиля используется уже существующий интерфейс фронтенда.

## Проверка

После установки зависимостей и применения миграций:

```bash
poetry run python manage.py check
poetry run python manage.py test catalog.test_commerce catalog.test_api
poetry run python manage.py makemigrations --check --dry-run
git diff --check
```

Тесты проверяют регистрацию, вход/выход, поля профиля, смену пароля, загрузку
аватара, гостевую корзину, сохранение корзины при входе и выходе, остатки и
некорректные запросы.
