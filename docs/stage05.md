# Оформление заказа и учебная оплата

Исходные страницы дополнены в `catalog/templates/frontend`, JS — в
`catalog/static/frontend/assets/js`. Пакет `diploma-frontend` этим этапом не изменяется.

## API

POST принимает JSON и требует CSRF-токен сессии. Ошибки: `{"errors":{"поле":"сообщение"}}`.
Поддерживаются URL с завершающим слешем и без него.

| URL | Метод | Назначение |
| --- | --- | --- |
| `/api/checkout` | GET | Корзина, данные покупателя, доставка и checkoutKey |
| `/api/checkout/register` | POST | Регистрация: fullName, email, phone, password, passwordReply |
| `/api/orders` | GET | История текущего пользователя |
| `/api/orders` | POST | Создание: checkoutKey, fullName, email, phone, city, address, deliveryType, paymentType, comment |
| `/api/order/<id>` | GET | Снимок своего заказа, сумма, статус и ошибка |
| `/api/payment/<id>` | GET | Свой заказ для оплаты |
| `/api/payment/<id>` | POST | В очередь: number (строка), paymentType; ответ 202 |
| `/api/account` | GET | Имя, аватар и последний заказ |

deliveryType: `ordinary` / `express`; paymentType: `online` / `someone`.
Статусы: `new` → `payment` → `paid` / `failed`; после ошибки доступна новая попытка.
Без авторизации API возвращает 401, чужой или удалённый заказ — 404.
Цена и товары запроса игнорируются: сервер читает свою корзину и предложения.
Повтор checkoutKey возвращает тот же заказ; повтор активной оплаты — ту же задачу.
Оплаченный заказ повторно оплатить нельзя (409).

## Очередь

PaymentJob — таблица устойчивой очереди. Уникальное ограничение разрешает только
одну активную попытку на заказ. Обработчик атомарно захватывает задачу с арендой
60 секунд, вызывает отдельный HTTP-сервис и фиксирует результат в транзакции.
После остановки просроченная задача подхватывается с тем же ключом. Сервис хранит
результат в своей SQLite-базе и повторно возвращает его по ключу.
Тайм-аут HTTP — 10 секунд. При недоступности: три попытки с задержками 5 и 10 секунд,
затем ошибка заказа и возможность новой оплаты. Номер очищается после завершения.

Сервис: `POST /pay`, JSON `{"key":"UUID","number":"12345678"}`,
заголовок `Authorization: Bearer <PAYMENT_SERVICE_TOKEN>`.
Ответ: `{"success":true}` или `{"success":false,"error":"причина"}`.
Номер повторно проверяется сервисом; номера и токен не записываются в журнал запросов.

## Сценарий проверки

1. Добавить товар, открыть корзину и оформление.
2. Проверить пустые поля, регистрацию гостя и ссылку «Я уже зарегистрирован».
3. Пройти данные, доставку, оплату и подтверждение с комментарием.
4. `123` отклоняется до постановки в очередь.
5. `12345670` даёт ошибку сервиса: она видна у заказа и в истории.
6. Повторить оплату с `12345678`: статус «Оплачен».
7. Проверить кабинет, последний заказ, профиль и историю.
8. Другим пользователем детали и оплата первого заказа недоступны.

Фильтр дополнен производителем и всеми типами характеристик, включая текст
без учёта регистра. Карточка показывает описание и окно добавления в корзину.
