# Мониторинг и внешнее хранилище

Интеграции дополняют проект: исходные шаблоны, записи пользователей и заказов
сохраняются. По умолчанию файлы остаются в `media/`, Sentry отключён без DSN.
Новые зависимости устанавливаются командой `poetry install`.

## Подготовка

Сделайте резервную копию базы и `media/`, затем выполните:

```bash
poetry run python manage.py migrate
poetry run python manage.py setup_operations --local-storage
docker compose -f infra/observability/compose.yaml --env-file infra/observability/.env --profile storage --profile linux up -d
```

Профиль `linux` предназначен для Ubuntu и добавляет метрики процессора, памяти
и диска. В Docker Desktop на Windows опустите `--profile linux`.
Команда подготовки создаёт случайные секреты; повторный запуск сохраняет их.
Файлы секретов и `.env` исключены из Git. Если уже настроено облачное S3,
используйте `setup_operations` без `--local-storage` и запускайте Compose без
профиля `storage`.

Перезапустите сайт и обработчик платежей, чтобы прочитать новые настройки.
Prometheus обращается к `host.docker.internal:8000`: для локальной проверки
добавьте `host.docker.internal` к существующему `DJANGO_ALLOWED_HOSTS` в `.env`
и запустите сайт на `0.0.0.0:8000`. Для сервера настройте в `prometheus.yml`
адрес доступного из контейнера WSGI/nginx; не добавляйте `*` в разрешённые хосты.

## Мониторинг

- Prometheus: `http://127.0.0.1:9090`, Targets → `megano` должен быть `UP`.
- Grafana: `http://127.0.0.1:3000`, пользователь `admin`, пароль находится
  в локальном `infra/observability/.env`. Панель «Megano — состояние приложения»
  подключается автоматически.
- `/health/` проверяет соединение с базой, возвращает 200 или 503 без деталей ошибки.
- `/metrics/` требует `Authorization: Bearer <METRICS_TOKEN>`; без токена
  доступ отключён. Метрики не содержат логинов, номеров заказов или карточных данных.

Панель показывает доступность сайта и базы, запросы, ошибки 5xx, задержки SQL,
состояние очереди, heartbeat обработчика, CPU и память Ubuntu.
Обработчик обновляет heartbeat каждые 10 секунд; после 45 секунд без обновления
показатель равен нулю. Prometheus содержит правила для остановленного сайта,
обработчика, недоступной базы, задержки платежей, ошибок и заполненного диска.
Они видны в Alerts; внешняя доставка уведомлений требует отдельной настройки
Alertmanager или Grafana и адреса получателя.

Счётчики запросов находятся в памяти процесса. Эта конфигурация рассчитана на
один процесс сайта; для нескольких WSGI-процессов требуется отдельная настройка
Prometheus multiprocess. Heartbeat и очередь хранятся в базе.
Данные Prometheus и Grafana сохраняются в Docker volumes. Для остановки
используйте `docker compose ... down` без `-v`.

## Sentry

Создайте проект Django в своём Sentry и добавьте в `.env`:

```dotenv
SENTRY_DSN=<DSN проекта>
SENTRY_ENVIRONMENT=production
SENTRY_RELEASE=megano-recommendations
```

Перезапустите сайт и обработчик. Исключения Django и ошибки обращения обработчика
к сервису оплаты отправляются через SDK. Пользователь, тело запроса, cookies,
заголовки, query string, breadcrumbs и локальные переменные исключены из событий.
Частота performance traces равна нулю. Не помещайте секреты в тексты исключений.
Без настоящего DSN внешняя доставка событий не выполняется.

## Перенос media без удаления исходников

Для локальной проверки используется S3-совместимый SeaweedFS в отдельном контейнере
с постоянным volume. Для Amazon S3 или Yandex Object Storage задайте bucket,
регион, endpoint и отдельные ключи в `.env`; публичный доступ к bucket не нужен.
Параметры перечислены в `.env.example`. Для AWS можно использовать IAM role,
оставив явные ключи пустыми.

Остановите сайт на время копирования, чтобы загрузки и удаления не меняли файлы.
Оставьте `MEDIA_STORAGE=local` до завершения проверки:

```bash
poetry run python manage.py create_media_bucket
poetry run python manage.py copy_media_to_s3
poetry run python manage.py copy_media_to_s3 --apply
poetry run python manage.py copy_media_to_s3 --verify
```

Первая команда создаёт bucket, только если его нет; для облачного bucket,
созданного заранее администратором, она необязательна. Вторая показывает план.
Копирование сохраняет имена и проверяет SHA256 каждого файла; повторный запуск
пропускает одинаковые файлы, а при отличающемся существующем объекте останавливается.
Локальные файлы и ссылки в базе не удаляются и не заменяются.

После успешной проверки установите `MEDIA_STORAGE=s3` в `.env` и перезапустите
сайт. Новые загрузки отправляются в bucket под префиксом `media/`. URL подписаны
и действуют один час. Проверьте существующие изображения и новую загрузку аватара.
При локальном хранилище URL `127.0.0.1:8333` должен быть доступен браузеру:
для браузера Windows добавьте в VirtualBox перенаправление порта 8333, как для 8000.
Для публичного сервера нужен доступный HTTPS endpoint объектного хранилища.
Статика остаётся локальной и собирается обычным `collectstatic`.

Для возврата к исходным файлам установите `MEDIA_STORAGE=local`; новые файлы,
загруженные уже в S3, перед этим нужно отдельно скопировать обратно.

[S3 storage](https://django-storages.readthedocs.io/en/latest/backends/amazon-S3.html),
