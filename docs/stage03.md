# Этап 3: витрина, каталог и отзывы

Подготовлено поверх второго этапа с исправлениями архивирования и подписей
объектов (пользователь отправил коммит `72dd81a` в MR !4).
Перед сдачей третьего этапа дождитесь принятия второго и учтите новые замечания.

## Что реализовано

- Главная: категории в два уровня, восемь популярных товаров, до шестнадцати
  лимитированных товаров, баннеры с переходом в каталог.
- Каталог: поиск без учёта регистра по названию и текстовым характеристикам,
  цена со скидкой, наличие, бесплатная доставка, производитель,
  одиночные и множественные характеристики, булевы характеристики.
- Сортировки по цене, покупкам, количеству отзывов и дате; пагинация.
- Карточка: изображения, описание, характеристики, предложения продавцов,
  скидка, остаток и отзывы с догрузкой по пять.
- Отзыв публикует только активный авторизованный пользователь. Автор берётся
  из сессии, проверяется CSRF, ошибки возвращаются рядом с полями, текст сохраняется
  при ошибке. Гостю форма не показывается.
- Архивированные товары и категории скрыты, предложения неактивных или
  архивированных продавцов исключены.

Оригинальный пакет фронтенда сохранён. Шаблоны и скрипты витрины переопределены
в приложении `catalog`. Vue загружается из поставляемых локальных файлов.
Новые зависимости и миграции не требуются.

## Принятые правила

Цена карточки — минимальная цена предложения с остатком; если остатков нет,
показывается минимальная цена доступных продавцов. Одновременно действующие
скидки не складываются: применяется максимальная. Цена округляется до копеек.
Бесплатная доставка товара определяется порогом из `DeliverySettings`.
Популярность — количество единиц в оплаченных неархивированных заказах;
`sort_index` имеет приоритет в блоке главной. Параметр API `rating` сортирует
по покупкам, а звёзды карточки показывают среднюю оценку отзывов.
В совместимом API тегов используются варианты характеристик;
фильтрация внутри одной множественной характеристики работает через «или»,
между разными характеристиками — через «и».

Регистрация, отдельная форма входа, корзина и заказы относятся к следующим
этапам. Для проверки отправки отзыва на этом этапе можно войти в админку
и открыть карточку в том же браузере. Названия объектов админки и архивирование
взяты из исправленного второго этапа.

## Перенос в Ubuntu

Распакуйте `stage-03.zip` в отдельную папку, например `~/Downloads/stage-03/`.
Для ранней проверки третьего этапа дождитесь, пока исправление разархивирования
будет закоммичено и отправлено в `feature/02-models`. Затем создайте отдельную
ветку от обновлённой ветки второго этапа. MR третьего этапа направьте в
`feature/02-models`, чтобы куратор видел только третий этап. Этот MR можно
отправить на проверку, пока MR второго этапа ещё открыт; сливать третий этап
до принятия второго не нужно.

```bash
cd ~/python_django_diploma
git status --short
git fetch origin
git switch feature/02-models
git pull --ff-only
git switch -c feature/03-storefront
git apply --check ~/Downloads/stage-03/stage-03.patch
git apply ~/Downloads/stage-03/stage-03.patch
poetry run python prepare-stage03.py
poetry run python manage.py check
poetry run python manage.py test catalog --noinput
poetry run python manage.py makemigrations --check --dry-run
git diff --check
```

Перед переключением веток рабочее дерево должно быть чистым. После применения
патча выполните проверки, сделайте коммит и отправьте `feature/03-storefront`.
Создайте MR `feature/03-storefront` → `feature/02-models` с названием
«Этап 3: витрина, каталог и отзывы». Это MR только для раннего ревью.
После принятия MR второго этапа сначала дождитесь его слияния в
`release/02-models`; затем перенесём третий этап в релизную ветку и направим
отдельный релизный MR в `master`.

Если проверка
патча сообщает конфликт, не применяйте его принудительно: сверяйте с принятой
версией второго этапа. `prepare-stage03.py` ставит `frontend` последним в списке
приложений для выбора новых шаблонов; существующие настройки сохраняются.
При `DEBUG=False` для обновления статики потребуется `collectstatic`.

Запуск для просмотра:

```bash
poetry run python manage.py runserver 127.0.0.1:8000
```

Если порт занят уже запущенным сервером, остановите его через Ctrl+C в том
терминале, где он работает. Ctrl+Z приостанавливает сервер и оставляет порт занятым.

## Демонстрационные данные

Для отдельной учебной базы сначала примените миграции и загрузите фикстуру
второго этапа `demo`, затем дополнительную фикстуру третьего этапа:

```bash
poetry run python manage.py migrate
poetry run python manage.py loaddata demo
poetry run python manage.py loaddata storefront_demo
```

Получится 24 товара (две страницы каталога) и семь отзывов у «Телефон 1».
Дополнительная фикстура использует учебные записи 1001/1002 и ID 2001–2006.
Загружайте её только в демонстрационную базу: `loaddata` обновляет записи с
совпавшими ID. Рабочая база и `.env` в пакет не входят.

## Проверка в браузере

1. Откройте `/`: популярные и лимитированные товары, переход из категории.
2. Откройте `/catalog/1002/`: поиск «ТЕЛЕФОН», производитель, NFC «Да/Нет»,
   память и цвета; комбинация фильтров и кнопка сброса.
3. Проверьте сортировку цены в обе стороны и переход между страницами.
4. Укажите минимальную цену выше максимальной: сообщение ошибки,
   введённые значения остаются в форме. Проверьте пустой результат.
5. `/sale/`: цена до скидки и после, переход в карточку.
6. `/product/1001/`: предложения, характеристики, пять отзывов и догрузка.
7. Войдите через `/admin/`, откройте карточку в этом же браузере, отправьте
   пустой отзыв, затем корректный. Пустой не сохраняется, корректный появляется.
8. Архивируйте учебный товар или его категорию: он исчезает из публичного API.

## API

`/api/categories`, `/api/catalog`, `/api/catalog/filters`,
`/api/products/popular`, `/api/products/limited`, `/api/sales`, `/api/banners`,
`/api/tags`, `/api/product/<id>`, `/api/product/<id>/reviews`.
Поддерживаются адреса с завершающим слешем и без него.
Список каталога: `items`, `currentPage`, `lastPage`, `total`;
фильтры передаются как `filter[name]`, `filter[minPrice]`,
`filter[maxPrice]`, `filter[available]`, `filter[freeDelivery]`,
`filter[manufacturer]`, `attributes[id]` или `attributes[id][]`.
Для категории используется `category`, для пагинации `currentPage` и `limit`.
Ошибки ввода: HTTP 400 и `errors` с названиями полей;
неизвестные объекты/страницы: 404; неподдерживаемые методы: 405.
